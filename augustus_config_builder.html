Step 5: Select Detectors

🔍 What are Detectors?

Detectors analyze LLM responses to determine if an attack succeeded (vulnerability found) or failed (model resisted).

Detector Types (How They Work)
🔤 Heuristic (Pattern Matching)

Fast keyword/regex matching. No LLM required.

dan.DAN, dan.STAN, always.Pass, always.Fail, snowball.*
🤖 ML-Based (Toxicity Models)

Pre-trained classifiers. No API key required.

toxiccomment.Toxic, perspective.Perspective, unsafecontent.*
⚖️ LLM-as-Judge

Uses an LLM to evaluate. Requires judge config in YAML.

judge.Judge, judge.Refusal
When to Use Each Selection Mode

✅ Auto: Best for most cases. Each probe knows its matching detector (e.g., dan.Dan_10_0 → dan.DAN)

🎯 Single: Force ONE detector for all probes. Use when you want consistent evaluation (e.g., all probes checked by toxiccomment.Toxic)

🔗 Pattern: Use multiple detectors matching a pattern (e.g., dan.* runs all DAN detectors)

Recommended: Use Auto unless you have a specific reason to override detector matching.
Single probe: use Auto, or choose the matching detector from the dropdown if you want to force one exact detector.
Category or glob: use Auto first. If you need manual control, choose a detector glob that matches the same attack family.
Judge detectors: if you select judge.Judge or judge.Refusal, complete the Judge section in Step 6.

Pattern Examples

dan.* — All DAN detectors | toxiccomment.* — All toxicity | * — Run all detectors

Judge Decision Settings

Conversation-based strategies use full dialogue history. Iterative strategies repeatedly refine prompts with attacker and judge feedback.

🎯 All Strategies Run all attack strategies for comprehensive testing
🎭 Crescendo Gradual escalation - Starts innocent, slowly shifts to harmful. Best for tone-tracking models. ~10 turns.
🐐 GOAT Aggressive technique switching - 7 adversarial techniques with Chain-of-Attack reasoning. Fast results in 3-5 turns.
🐉 Hydra Backtracking on refusal - Erases failed turns, retries with new approach. Best for stubborn models.
😈 Mischievous User Casual persona probing - Acts like innocent curious user. Bypasses attack-detection heuristics. ~5 turns.
🔗 Iterative PAIR Prompt Auto Iterative Refinement - Attacker LLM refines prompts based on target responses. Automated optimization.
🌲 TAP Tree of Attack Prompts - Explores branching attack paths with pruning. Thorough but resource-intensive.

Step 7: Execution And Output Settings

Harness (Execution Strategy)

Controls how probes are executed against the target LLM.

probewise.Probewise (Default) — Runs each probe independently, one at a time. Best for standard testing.

batch.Batch — Groups multiple probes together for efficiency. Faster for large probe sets, but less granular results.

agentwise.Agentwise — Designed for testing AI agents/orchestrators. Maintains agent context across probe attempts.

Buff (Prompt Transformation)

Transforms prompts to evade detection or test different attack vectors.

Encoding Buffs: encoding.Base64, encoding.ROT13, encoding.Hex — Encode prompts to bypass filters

Paraphrase: paraphrase.Fast, paraphrase.PegasusT5 — Rephrase prompts to avoid detection

Poetry: poetry.MetaPrompt — Convert prompts to poetic form

Smuggling: smuggling.FunctionMask, smuggling.Hypothetical — Hide intent in fictional scenarios

Flip: flip.WordOrder, flip.CharsInWord — Reverse/scramble text

⚙️ Execution Settings

How To Choose These

Timeout limits the total scan runtime. Probe Timeout limits one probe attempt. Concurrency controls how many probes run in parallel. Lower concurrency is safer for local models; higher concurrency is better for fast cloud APIs.
